# Deployment Guide

## Prerequisites

1. **GitHub Account** - For code hosting
2. **Railway.app Account** - For backend hosting
3. **Streamlit Cloud Account** - For frontend hosting
4. **Git CLI** - For version control

## Phase 1: Backend Deployment (Railway.app)

### 1.1 Setup Railway Project

```bash
# Install Railway CLI
npm install -g @railway/cli

# Navigate to backend
cd backend

# Login to Railway
railway login

# Initialize project
railway init

# This will prompt:
# - Select "New project"  
# - Select "PostgreSQL" for database
# - Confirm project name
```

### 1.2 Environment Variables

In Railway dashboard, add:

```
DATABASE_URL=postgresql://...  # Auto-generated by Railway
CORS_ORIGINS=["https://your-streamlit-app.streamlit.app"]
API_V1_PREFIX=/api/v1
PROJECT_NAME=AeroCorridor
VERSION=2.0.0
VOXEL_SIZE_M=5.0
CRUISE_ALTITUDE_AGL_M=100.0
MAX_ALTITUDE_AGL_M=200.0
TELEMETRY_UPDATE_INTERVAL_MS=500
DRONE_COUNT=3
BENGALURU_GROUND_ELEV_MSL=920.0
ENABLE_TELEMETRY_SIMULATION=true
```

### 1.3 Deploy

```bash
# From backend directory
railway up

# Or via GitHub
railway link  # Connect your repo
# Then auto-deploys on git push
```

**Result**: Backend URL like `https://aerocorridor-backend.railway.app`

### 1.4 Seed Database

In Railway PostgreSQL shell:
```bash
# Connect to PostgreSQL
railway db:connect

# Run seeding script (upload seed_db.py first)
python seed_db.py
```

Or seed via API after deployment:
```bash
curl -X POST https://your-backend.railway.app/api/v1/seed
```

### 1.5 Verify Deployment

```bash
curl https://your-backend.railway.app/health
# Should return: {"status": "healthy"}
```

## Phase 2: Frontend Deployment (Streamlit Cloud)

### 2.1 Prepare Repository

```bash
# From project root
git init
git add .
git commit -m "AeroCorridor: Backend complete"

# Push to GitHub
git remote add origin https://github.com/yourusername/aerocorridor.git
git branch -M main
git push -u origin main
```

### 2.2 Connect to Streamlit Cloud

1. Visit: https://share.streamlit.io/
2. Click: **"New app"**
3. Select:
   - **GitHub repository**: aerocorridor
   - **Branch**: main
   - **Main file path**: frontend/app.py

### 2.3 Set Secrets

After app appears in dashboard:

1. Click on app → **Settings** → **Secrets**
2. Add:
   ```
   API_URL = "https://your-railroad-backend.railway.app"
   ```

### 2.4 Deploy & Verify

- Streamlit Cloud auto-deploys
- App URL: `https://your-username-aerocorridor.streamlit.app`
- View logs in dashboard

## Phase 3: Alternative - Supabase Database Deployment

**Note:** This is an alternative to Railway PostgreSQL. Use either Railway's PostgreSQL OR Supabase, not both.

### 3.1 Create Supabase Project

1. Visit: https://supabase.com
2. Sign up (free tier available)
3. Click **"New Project"**
4. Enter:
   - **Name**: aerocorridor
   - **Database Password**: (save somewhere safe!)
   - **Region**: Closest to your region
5. Wait for initialization (~2 minutes)

### 3.2 Get Supabase Connection String

1. In Supabase dashboard, click **Settings** ⚙️
2. Go to **Database** → **Connection string**
3. Copy the **URI** (PostgreSQL format)
4. Format: `postgresql://postgres:PASSWORD@PROJECT_ID.supabase.co:5432/postgres`

### 3.3 Enable PostGIS Extension

In Supabase **SQL Editor**, run:
```sql
CREATE EXTENSION IF NOT EXISTS postgis;
CREATE EXTENSION IF NOT EXISTS postgis_topology;
```

### 3.4 Update Railway Environment Variables

Replace `DATABASE_URL` with your Supabase connection string:

```
DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@YOUR_PROJECT_ID.supabase.co:5432/postgres
SUPABASE_MODE=true
DB_POOL_SIZE=5
```

Keep other variables the same:
```
CORS_ORIGINS=["https://your-streamlit-app.streamlit.app"]
API_V1_PREFIX=/api/v1
PROJECT_NAME=AeroCorridor
VERSION=2.0.0
# ... rest of variables
```

### 3.5 Initialize Database

After changing `DATABASE_URL`, redeploy backend:

```bash
railroad redeploy
```

Then seed data via Supabase SQL Editor or via API after deployment:
```bash
curl -X POST https://your-backend.railway.app/api/v1/seed
```

### 3.6 Create Spatial Indexes (Optional but Recommended)

In Supabase **SQL Editor**:
```sql
-- Performance indexes
CREATE INDEX IF NOT EXISTS idx_buildings_location ON buildings USING GIST(location);
CREATE INDEX IF NOT EXISTS idx_delivery_nodes_location ON delivery_nodes USING GIST(location);
CREATE INDEX IF NOT EXISTS idx_obstacles_base_loc ON obstacles USING GIST(base_location);
CREATE INDEX IF NOT EXISTS idx_risk_voxel_center ON risk_voxels USING GIST(center);
CREATE INDEX IF NOT EXISTS idx_orders_status ON orders(status);
CREATE INDEX IF NOT EXISTS idx_telemetry_drone_id ON telemetry(drone_id);
```

### 3.7 Supabase vs Railway PostgreSQL

| Feature | Railway PostgreSQL | Supabase |
|---------|-------------------|----------|
| **Cost** | ~$15-20/mo | Free-$25/mo |
| **Managed** | Yes | Yes |
| **PostGIS** | ✅ | ✅ |
| **SSL Required** | No | **Yes** |
| **Connections** | Unlimited | Limited by tier |
| **Setup Time** | 5 min | 10 min |
| **Recommended For** | Simplicity | Scalability |

**Choose Supabase if**: You want separate database management, need auto-scaling, or prefer managed services.

**Choose Railway PostgreSQL if**: You want integrated deployment with simpler setup.

## Troubleshooting Deployment

### Backend Won't Deploy

**Error**: Docker build failed
- Solution: Ensure `requirements.txt` has all dependencies
- Check: `pip freeze > requirements.txt`

**Error**: Connection to database failed
- Solution: Verify `DATABASE_URL` in environment
- Check: Is PostgreSQL plugin added in Railway?

### Frontend Won't Connect to Backend

**Error**: CORS error in browser console
- Solution: Add Streamlit URL to `CORS_ORIGINS` in backend env vars
- Format: `CORS_ORIGINS=["https://your-app.streamlit.app"]`

**Error**: API URL returns 404
- Solution: Check `API_URL` in `.streamlit/secrets.toml`
- It should be the full Railway backend URL

### WebSocket Connection Fails

**Error**: WebSocket connection refused
- Solution: Ensure WebSocket endpoint is enabled
- Backend must expose `/api/v1/telemetry/ws`
- Railway supports WebSocket by default

### Database Seeding Issues

**Error**: "relation does not exist"
- Solution: Run `seed_db.py` after PostgreSQL is created
- Or: Execute `init.sql` first for indexes

## Scaling & Performance

### Backend

1. **Scale deployment**
   ```bash
   railway scale web=2  # 2 instances
   ```

2. **Database connection pooling**
   - Already configured in `config.py`
   - Pool size: min 10, max 30

3. **Caching headers**
   - Add Cache-Control for static routes
   - 60s cache for `/map/buildings/geojson`

### Frontend

1. **Streamlit performance**
   - Use `@st.cache_data` for expensive calls
   - Already implemented in API client

2. **Map rendering**
   - Folium maps can be slow with >1000 markers
   - Cluster markers if needed

## Updates & Maintenance

### Update Dependencies

```bash
# Local testing
pip install --upgrade -r backend/requirements.txt
pip install --upgrade -r frontend/requirements.txt

# Commit changes
git add requirements.txt
git commit -m "Update dependencies"
git push  # Auto-deploys
```

### Database Migrations

When schema changes:

1. Create migration script in `backend/migrations/`
2. Run during deployment window
3. Test thoroughly locally first

Example:
```python
# backend/migrations/001_add_field.sql
ALTER TABLE orders ADD COLUMN priority INTEGER DEFAULT 0;
```

## Security Checklist

- [ ] Environment variables stored in Railway/Streamlit dashboards
- [ ] `.env` files are `.gitignore`d
- [ ] `secrets.toml` is `.gitignore`d
- [ ] CORS origins restricted to actual frontend domain
- [ ] Database credentials use strong passwords
- [ ] PostgreSQL runs in private network
- [ ] API uses HTTPS (default for Railway & Streamlit)
- [ ] No hardcoded API keys in code

## Rollback Procedure

### If Backend Breaks

```bash
# View deployment history
railway history

# Rollback to previous version
railway redeploy [DEPLOYMENT_ID]
```

### If Frontend Breaks

In Streamlit Cloud:
- Click app → Settings → Versions
- Select previous working version
- "Restore"
